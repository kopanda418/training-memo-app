# 筋トレメモアプリ 連携ガイド(トレーニングプラン→予定インポート用)

別プロジェクト(週次プラン生成側)が「筋トレメモアプリ」にプランを取り込む import 用 JSON を
組み立てるための最小限の情報。アプリ本体のソースは別リポジトリ(非公開)にあり、この文書だけで完結する。

## 連携経路: プラン取り込み(実装済み・実機動作確認済み)

設定画面の「プラン取り込み」から、専用フォーマットの小さな JSON を取り込める
(`docs/decisions.md` ADR-010 / ADR-012 / ADR-013)。内部 id は不要で、種目名・タグ名だけでプランを
組み立てられる。2026-07-10 に実機(本番デプロイ)で、既存種目・新規種目・新規タグ・冪等性
(同一ファイルの再取り込み)を含めて動作確認済み。

- 既定(非破壊): まだ記録がない `date + 種目 + タグ` の組み合わせにだけセットを追加する。
  既に記録がある組み合わせは**丸ごとスキップ**(冪等。同じファイルを何度取り込んでも重複しない)
- **上書きオプション(2026-08-19 追加)**: アプリ側で「重複分を上書きする」を選ぶと、既に記録が
  ある組み合わせも既存セットを削除して新しいセットに置き換えられる(確認ダイアログで対象一覧を
  提示してから実行)。生成側で特別な対応は不要(取り込むアプリ側の操作のみ)
- 未登録の種目・タグ・**部位(bodyPart)**は name 一致で新規作成する
- 取り込み前にプレビュー(追加/スキップまたは上書き/新規作成の一覧)が出るので、name の表記ゆれ
  による意図しない新規種目作成はその場で確認できる

旧来の「全データエクスポート→編集→復元(全置換)」という往復は不要になった。

## プラン欄とユーザー欄は別枠(2026-08-20 / ADR-013)

アプリのメモ欄は「プランが書く欄」と「ユーザーが書く欄」に分かれている。**生成側が書けるのは
プラン欄だけ**で、ユーザーがジムで書いた内容を消すことはない。

| 粒度      | プラン欄(生成側が書く)            | ユーザー欄(ユーザーが書く)     |
| --------- | --------------------------------- | ------------------------------ |
| セット    | `sets[].memo` → アプリの「予定」  | セットメモ(取り込みは触らない) |
| 種目×タグ | `items[].note` → アプリの「予定」 | 種目メモ(取り込みは触らない)   |
| 日全体    | なし                              | 日メモ(取り込みは触らない)     |

- プラン欄はアプリ上で**読み取り専用**(青い「予定」ラベル付き)。ユーザーは編集しない
- ユーザーが実施中にセットメモ・種目メモへ何を書いても、**次の取り込み(上書きを含む)で消えない**。
  上書き時は既存セットのユーザーメモをセット順で新しいセットへ引き継ぐ
- したがって生成側は、ユーザーのメモを「実施結果のフィードバック」として一方向に読むだけでよい。
  ユーザーの書き込みを避けるために遠慮する必要も、書き方を指示する必要もない

## JSON フォーマット

```ts
interface PlanImportFile {
  app: 'training-memo-app'
  kind: 'plan-import'
  formatVersion: 1
  days: {
    date: string // "YYYY-MM-DD"
    location?: string // 場所名(任意)。新規に日を作る場合のみ適用(既存日は上書きしない)
    items: {
      exercise: string // 種目名。既存の種目マスタと name 完全一致で照合
      bodyPart?: string // 新規種目を作る場合のみ必須。デフォルト7部位("胸","背中","脚",
      // "肩","腕","腹","その他")以外の任意の文字列も指定可(例: "体幹")。
      // 部位マスタに未登録なら部位自体も自動作成される
      tag?: string // タグ名(省略でタグなし)。未登録なら新規作成
      note?: string // この種目のプラン指示(全セット共通)。フォーム注意点・中止条件など。
      // アプリでは種目メモの上に読み取り専用で表示される(書き方は下記ルール参照)
      sets: {
        weight: number // 目標重量(必須)
        unit?: 'kg' | 'lbs' // 省略時はアプリ設定の defaultUnit
        reps?: number // 省略時 0 = 「未実施(予定)」。週間集計・MAX判定から自動除外される
        isBodyweight?: boolean
        isWarmup?: boolean // ウォームアップセットにする(省略時 false)。週間集計・MAX判定から除外される
        attributes?: string[] // セット属性(任意テキスト、複数可。例: ["左","フル","DS"])。
        // 記録画面のセット属性チップとして表示される。既存の属性バンクと突き合わせはせず文字列をそのまま保存
        memo?: string // このセットのプラン指示(短い1行)。書き方は下記ルール参照
      }[]
    }[]
  }[]
}
```

### 例

```json
{
  "app": "training-memo-app",
  "kind": "plan-import",
  "formatVersion": 1,
  "days": [
    {
      "date": "2026-07-14",
      "items": [
        {
          "exercise": "ベンチプレス",

          "sets": [
            { "weight": 60, "reps": 8, "isWarmup": true, "memo": "アップ" },
            { "weight": 82.5, "memo": "5回 RPE8" },
            { "weight": 82.5, "memo": "5回 RPE8" },
            { "weight": 82.5, "attributes": ["ドロップセット"], "memo": "5回 限界なら4回で可" }
          ]
        }
      ]
    }
  ]
}
```

## メモの書き方ルール(重要)

長文のメモは記録画面を圧迫し、セット中に読むべき情報(重量・回数・中止条件)が埋もれる。
**アプリに入れるのは「ジムで実行するために要る情報」だけ**にする。

### 種目の `note` に書くこと(全セット共通・最大3項目・全体で 100 字以内目安)

- **フォーム上の注意点**: 「肩甲骨を寄せて肘は45度」「膝が内に入らないよう」
- **中止条件**: 「挙上速度が落ちたら終了」「腰に張りが出たらその時点で終了」
- **セット間の休憩**: 「休憩3分」

### セットの `memo` に書くこと(そのセット固有の指示だけ・1行・全角20字以内目安)

- 目標レップと強度: 「5回 RPE8」「8〜10回」
- そのセットだけの条件: 「限界まで」「余裕あれば+2.5kg」「アップ」
- 全セット同じ内容なら種目の `note` に 1 回だけ書き、`memo` は目標レップだけにする

### 書かないこと(アプリに入れない)

- **なぜその重量・回数なのかの経緯**(前回比、増量率、疲労を考慮した理由など)
- **週次/月次の周期化の説明、理論的背景、狙う適応**
- **前回セッションの分析・振り返り**(ユーザーが自分で種目メモに書く欄)
- **励ましや前置き**(「無理せず」「調子を見ながら」など)

これらはプラン生成側のドキュメント(またはチャット上の説明)に置く。アプリはジムで開く実行画面
であって、プランの説明書ではない。

### 例: 悪い / 良い

```
悪い(セットの memo):
  "先週は80kgで5回×3セットを余裕を持って完遂できており、疲労も残っていないため
   今週は2.5kg増やして82.5kgに設定します。フォームは肩甲骨を寄せて、肘の角度は
   45度を維持してください。挙上速度が明らかに落ちたら無理をせず終了してください。"

良い(セットの memo):
  "5回 RPE8"
良い(種目の note に 1 回だけ):
  "フォーム: 肩甲骨を寄せ肘45度 / 中止: 挙上速度が落ちたら終了 / 休憩3分"
```

## 生成側で気をつけること

- **種目名・タグ名はこのアプリの既存マスタと完全一致(trim後)させる。** 表記ゆれ(例:
  "スクワット" vs "バーベルスクワット")は別種目として新規作成されてしまう。可能なら
  ユーザーに既存の種目・タグ名一覧を一度確認してもらい、生成側でも固定の名称リストとして
  保持するのが安全
- 新規種目を作る場合は `bodyPart` を必ず入れる(省略するとその項目はエラーになり取り込まれない)。
  `bodyPart` はデフォルト7部位に限らず任意の文字列を指定でき、未登録なら部位マスタも自動作成される
  (2026-07-10 修正。それ以前は部位が未登録のまま種目だけ作られ、種目選択・種目管理のタブ UI から
  選べなくなる不具合があった)
- `reps` は基本的に省略してよい(0 = 予定。ジムで実施後にユーザーがアプリ上で実績へ書き換える)
- **同じ日付×種目×タグへ内容を差し替えたい場合**: 既定ではスキップされるだけだが、ユーザーが
  アプリの取り込み画面で「重複分を上書きする」を選べば、その組み合わせの既存セットを削除して
  ファイルの内容に置き換えられる(確認ダイアログあり)。生成側のファイル形式は変わらない。
  上書きしてもユーザーが書いたセットメモ・種目メモは残る(ADR-013)
- **種目の指示(`note`)を消したい場合**は、そのブロックを `note` なしで取り込み直す(上書き)。
  プラン欄だけが消え、ユーザーの種目メモは残る
- ファイルは小さくてよい(直近1〜2週間分の新規プランだけを含めれば十分。過去分・実績データは
  一切含める必要がない)
- `items[].note` と「予定」表示に対応したのはアプリ **v1.0.24** から。それ以前のバージョンでは
  `note` は無視される(設定画面下部のバージョン表記で確認できる)
