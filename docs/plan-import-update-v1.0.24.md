# 【連絡】プラン取り込みのメモ欄が分かれました(筋トレメモアプリ v1.0.24 / 2026-08-20)

宛先: 週次トレーニングプランを生成しているプロジェクト
関連: `plan-import-guide.md`(フォーマットの正本。この文書と一緒に更新済み)

## 3 行サマリ

1. これまで**セットの `memo` に全部書いていた**指示を、**種目単位の `items[].note`(新設)**と
   **セット単位の `sets[].memo`** に分けて書く。
2. アプリ側では両方とも青い「予定」ラベル付きの**読み取り専用**として表示される。
   ユーザーが書くメモ欄とは物理的に別のフィールドなので、**混ざらないし、消し合わない**。
3. 長文は書かない。アプリに載せるのは**ジムで実行するために要る情報だけ**
   (何をどれだけ / フォーム注意点 / 中止条件)。理由や経緯はプラン生成側の説明に置く。

---

## 1. どのフィールドに何を書くか(早見表)

プラン JSON で**書けるのはこの 2 つだけ**です。ほかのメモ欄はユーザー専用で、こちらからは書けません
(書く手段がありません)。

| フィールド                | 粒度        | ここに書くもの                                                     | 分量の目安              |
| ------------------------- | ----------- | ------------------------------------------------------------------ | ----------------------- |
| `items[].note` **(新設)** | 種目×タグ   | 全セット共通の指示。**フォーム注意点 / 中止条件 / セット間の休憩** | 最大 3 項目・100 字以内 |
| `sets[].memo`             | セット 1 本 | **そのセットだけの指示**。目標レップと強度、そのセット固有の条件   | 1 行・全角 20 字以内    |

アプリ側での格納先と表示(参考):

| プラン JSON    | アプリ内フィールド    | 画面での見え方                             |
| -------------- | --------------------- | ------------------------------------------ |
| `items[].note` | `blockNotes.planNote` | 種目名の下・種目メモの上に青いカードで表示 |
| `sets[].memo`  | `sets.planMemo`       | 各セット行に「予定 5回 RPE8」と表示        |

**ユーザー専用(こちらからは書かない・書けない)**

| アプリの欄 | データ上の場所    | 用途                                  |
| ---------- | ----------------- | ------------------------------------- |
| セットメモ | `sets.memo`       | そのセットでの気づき(例:「肩が痛い」) |
| 種目メモ   | `blockNotes.note` | その日のその種目の感想                |
| 日メモ     | `days.note`       | その日全体の体調・環境                |

## 2. 迷ったときの判断フロー

書きたい 1 文について、上から順に当てはめてください。

```
その文は…

(1) 「なぜこの重量/回数にしたか」「先週との比較」「周期化の狙い」か?
      → アプリには書かない。プラン生成側の説明(チャット・別ドキュメント)に置く

(2) その種目の全セットに共通する注意か?(フォーム・中止条件・休憩)
      → items[].note に 1 回だけ書く

(3) そのセット固有の指示か?(目標レップ、強度、アップ、限界まで)
      → sets[].memo に 1 行で書く

(4) ユーザーが実施後に感じることか?(痛み・感想・調子)
      → 書かない。ユーザーがセットメモ/種目メモに自分で書く欄
```

判断に迷う例:

- 「挙上速度が落ちたら終了」→ 全セット共通の**中止条件** → `items[].note`
- 「最終セットだけ限界まで」→ そのセット固有 → 該当セットの `sets[].memo` に「限界まで」
- 「先週 80kg×5 を余裕で完遂したので +2.5kg」→ **経緯なので書かない**
- 「無理せず調子を見ながら」→ 判断基準がないので書かない(中止条件として具体化するなら
  「肩に痛みが出たら終了」と `items[].note` へ)

## 3. 書き方の具体ルール

### `items[].note`(種目単位)

- 入れてよいのは次の 3 種類だけ。順序もこの順で統一すると読みやすい
  1. **フォーム**: 「肩甲骨を寄せ肘45度」
  2. **中止条件**: 「挙上速度が落ちたら終了」「肩に痛みが出たら終了」
  3. **休憩**: 「休憩3分」
- 区切りは `/`。全体で 100 字以内
- 例: `"フォーム: 肩甲骨を寄せ肘45度 / 中止: 挙上速度が落ちたら終了 / 休憩3分"`

### `sets[].memo`(セット単位)

- 目標レップ + 強度を最短で: `"5回 RPE8"` `"8〜10回"`
- そのセットだけの条件があれば足す: `"5回 限界なら4回で可"` `"アップ"` `"余裕あれば+2.5kg"`
- 全セット同じ指示なら、無理に変化をつけず同じ 1 行を繰り返してよい
- **禁止**: 2 行以上、説明文、`items[].note` の内容の再掲

## 4. Before / After(同じプランの書き分け)

### Before(これまで・NG)

```json
{
  "exercise": "ベンチプレス",
  "sets": [
    {
      "weight": 82.5,
      "memo": "先週は80kgで5回×3セットを余裕を持って完遂できており、疲労も残っていないため今週は2.5kg増やして82.5kgに設定します。フォームは肩甲骨を寄せて、肘の角度は45度を維持してください。挙上速度が明らかに落ちたら無理をせず終了してください。"
    },
    { "weight": 82.5, "memo": "同上。フォームを崩さないように..." }
  ]
}
```

### After(これから・OK)

```json
{
  "exercise": "ベンチプレス",
  "tag": "高重量日",
  "note": "フォーム: 肩甲骨を寄せ肘45度 / 中止: 挙上速度が落ちたら終了 / 休憩3分",
  "sets": [
    { "weight": 60, "reps": 8, "isWarmup": true, "memo": "アップ" },
    { "weight": 82.5, "memo": "5回 RPE8" },
    { "weight": 82.5, "memo": "5回 RPE8" },
    { "weight": 82.5, "memo": "5回 限界なら4回で可" }
  ]
}
```

「+2.5kg にした理由」はプラン提示時の会話や、生成側が持つ週次プラン文書に書いてください
(アプリはジムで開く実行画面であって、プランの説明書ではありません)。

## 5. ユーザーが書いた内容を読むとき

ユーザーが渡してくる**バックアップ JSON(全データ書き出し)**を分析に使う場合、
自分が書いた指示とユーザーの実績メモは次のように区別できます。

| 読みたいもの                 | 見るフィールド                                       |
| ---------------------------- | ---------------------------------------------------- |
| 自分が前回書いたセット指示   | `sets[].planMemo`                                    |
| 自分が前回書いた種目指示     | `blockNotes[].planNote`                              |
| **ユーザーのセットの気づき** | `sets[].memo`                                        |
| **ユーザーの種目の感想**     | `blockNotes[].note`                                  |
| **ユーザーのその日の感想**   | `days[].note`                                        |
| 実績                         | `sets[].reps` / `weight` / `rpe`(`reps: 0` は未実施) |

- v1.0.24 より前に取り込んだプランの文言は `sets[].memo` に残っています(過去分は移していません)。
  古い日付のデータを読むときだけ、`memo` にプラン文が混ざっている可能性がある点に注意。
- 詳細は `export-format.md` を参照。

## 6. 上書き取り込みの挙動(重要)

同じ `日付 × 種目 × タグ` を作り直したいとき、ユーザーがアプリで「重複分を上書きする」を選ぶと
置き換えが起きます。そのとき:

| 項目                           | どうなるか                                 |
| ------------------------------ | ------------------------------------------ |
| 重量・回数・isWarmup           | 新しいプランの内容に置き換わる             |
| `sets[].memo`(プラン指示)      | 新しい内容に置き換わる                     |
| `items[].note`(プラン指示)     | 新しい内容に置き換わる。省略すれば消える   |
| **ユーザーのセットメモ**       | **残る**(セット順で新しいセットへ引き継ぐ) |
| **ユーザーの種目メモ・日メモ** | **残る**                                   |

つまり、**ユーザーが何か書き込んでいても遠慮なくプランを差し替えられます。**
ただしセット数を減らすと、余ったセットに紐づいていたユーザーメモは失われます(セット順で対応付け
するため)。実施済みの日を上書きするのは避け、原則として未実施日のプラン修正に使ってください。

## 7. 変わっていない点

- `app` / `kind` / `formatVersion` は据え置き(`formatVersion: 1` のまま)
- 種目名・タグ名は既存マスタと**完全一致**が必要(表記ゆれは新規種目が作られる)
- 新規種目には `bodyPart` が必須
- `reps` 省略(= 0)で「未実施の予定」。集計・MAX 判定から自動除外される
- ファイルは直近 1〜2 週間分の新規プランだけでよい

## 8. 生成前チェックリスト

- [ ] `sets[].memo` は 1 行・全角 20 字以内か
- [ ] 全セット共通の内容を各セットに繰り返していないか(→ `items[].note` へ 1 回)
- [ ] 中止条件が書かれているか(高強度セットのある種目)
- [ ] 「なぜこの重量か」の説明が JSON に混ざっていないか
- [ ] 種目名・タグ名は既存マスタと完全一致しているか
- [ ] 新規種目に `bodyPart` を付けたか

## 9. 前提バージョン

`items[].note` と「予定」表示は**アプリ v1.0.24 以降**で動作します。それより古いバージョンでは
`note` は無視され、`sets[].memo` はユーザー欄に入ります(アプリの設定画面下部でバージョン確認可)。
